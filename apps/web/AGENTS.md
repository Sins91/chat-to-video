# Web Agent Rules

本文件补充仓库根规则，适用于 `apps/web`。

## AI Elements 组件使用约束

- 新增或修改 Agent 相关界面与交互功能时，包括对话、消息、工具调用与结果、推理过程、任务状态、队列、提示输入、模型选择及其组合视图，必须优先复用或扩展 `src/components/ai-elements` 中已有的 AI Elements 组件；现有目录缺少所需组件时，应先核查 AI Elements 当前组件能力和适用于本项目的官方实现。
- 不得为方便重复实现与 AI Elements 职责相同的平行组件，也不得直接引入另一套 Agent UI 组件库。AI Elements 组件位于项目源码内时，应优先通过组合、props、样式和受控的本地扩展满足需求。
- 只有确认 AI Elements 现有组件及其扩展能力无法满足相关需求时，才可以考虑自定义替代组件或其他组件库。采取该方案前必须暂停实现，向用户说明具体能力缺口、已核查的 AI Elements 方案、拟采用方案及其对交互一致性、可访问性和依赖的影响，并取得用户明确确认；未经确认不得实施。
- 复用或扩展 AI Elements 时仍须遵守下方 Tailwind CSS、语义设计 token 和信息密度规则，不得把组件复用作为绕过现有界面规范的理由。

## Agent 界面样式

### 规划卡片信息密度

- 右侧展示区域中的研究、方案、脚本、场景、素材、剪辑等所有规划卡片，应以当前阶段的核心内容和影响用户决策的信息为主，减少辅助说明与重复元数据，避免形成高密度标签墙。
- 默认不展示“生成视频”“生成图片”“标题卡”“已有素材”“需要动态”“静态可用”“推荐方向”等类型、来源、能力或状态提示；只有该信息会改变用户下一步操作或需要用户处理时才可展示。
- 必须保留标题卡正文、时长、成本、场景顺序、剪辑参数等实际内容。必要的次级信息优先使用低强调度的普通文本，不使用彩色徽标或胶囊标签。
- 新增规划阶段或规划卡片时必须复用本规则，不得仅对分镜写作卡片做特殊处理。

- Agent 工作区及其聊天、工作流、预览组件，新增或修改样式时优先直接使用 Tailwind CSS 工具类；布局、间距、尺寸、排版、颜色、状态、响应式和简单选择器不得为方便而新增页面级自定义 CSS 类。
- 颜色优先使用 Tailwind 暴露的语义设计 token（如 `bg-background`、`text-foreground`、`border-border`），避免新增硬编码色值；确需动态值时优先使用 Tailwind 任意值或 CSS 变量。
- 仅当样式属于跨组件主题 token、全局基础规则、复杂且重复使用的多层背景或动画，或第三方组件无法通过 `className` 覆盖时保留 CSS；保留时使用语义化类名，并简短说明 Tailwind 不适合表达的原因。
- 修改 Agent 界面时，应迁移所触及范围内可等价表达的旧自定义 CSS 类；不得借机重写无关页面或删除仍被其他页面依赖的兼容规则。
