# Shared Package Agent Rules

本文件适用于 `packages/**`，补充仓库根目录的总体架构原则。各共享包的专属 `AGENTS.md` 继续定义更具体的边界。

## 依赖与公共 API

- 共享包只承载稳定协议或基础能力，不得反向依赖 `apps/*`，不得为某个应用引入隐式运行时或供应商耦合。
- 对外导出保持最小化，并通过包的公共入口暴露；消费者不得深路径导入内部文件。
- 内部 workspace 依赖使用 `workspace:*`，外部依赖使用精确版本。只使用 pnpm，并从仓库根目录以精确 workspace 过滤器安装。
- 不依赖其他共享包的传递依赖；确需直接使用时，在当前 workspace 声明显式、精确版本。

## TypeScript 与实现

- 保持 `strict` 和 `noUncheckedIndexedAccess`；不使用 `any`、非空断言或关闭规则掩盖类型问题。外部或跨边界输入使用 `unknown`，验证后再收窄。
- 遵循所在 workspace 的 ESM/NodeNext 配置。命名表达业务含义，时间值写明单位，ID 不混用，注释解释约束而非复述代码。
- 名称或职责为通用管线、共享编排、注册表或 pipeline service 的实现，必须用至少一个具有不同阶段集合或顺序的测试夹具证明扩展性；新增管线不得要求修改通用算法。
- 不顺手格式化、重写或扩张无关公共 API；保留用户已有改动与文件风格。

## 数据与验证

- 客户端输入、队列载荷、模型输出、环境变量和外部服务响应都视为不可信；基础包不得提供绕过边界校验的便捷入口。
- 修复缺陷时先补复现测试；新增行为覆盖成功路径、输入校验和关键失败路径。外部服务、数据库和媒体进程在单元测试中以接口替身隔离。
- 除非用户明确要求，不运行测试、构建或基础设施；默认只执行改动 workspace 的 `typecheck` 与 `lint`，并在完成报告中列出未运行项。
- 修改前检查 `git status`、相关源码、配置和测试。行为、公共协议、依赖或架构边界变化时同步更新必要文档。
